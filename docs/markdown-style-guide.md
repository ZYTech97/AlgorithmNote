# AlgorithmNote Markdown 编写规范

本规范适用于本仓库的算法学习笔记，保证 GitHub 网页端和移动端正确显示数学公式与示意图。

## 1. 数学公式

GitHub 支持 LaTeX，但 Markdown 解析可能与 `*`、`_` 等字符发生冲突。经实际页面验证，优先采用以下写法。

### 1.1 行内公式

使用 GitHub 支持的 **美元符号 + 反引号** 定界语法：

~~~markdown
满足条件的最大位置为 $\x60i^{*}\x60$。
时间复杂度为 $\x60O(\\log(m+1))\x60$。
~~~

上面的 `\x60` 表示反引号字符（`），实际 Markdown 应写为：

- `$` + 反引号 + `i^{*}` + 反引号 + `$`
- 例如：$\x60i^{*}\x60$

### 1.2 独立公式

优先使用 GitHub 的 `math` 围栏代码块，不使用 `$$` 作为本仓库默认格式：

~~~markdown
```math
i+j=\left\lfloor\frac{m+n+1}{2}\right\rfloor
```
~~~

### 1.3 公式语法

- 上标、下标显式加花括号：`i^{*}`、`a_{i}`，避免 `i^*` 等容易与 Markdown 冲突的写法。
- **比较符号**：在 `math` 代码块中需要严格小于号时使用 `\lt`，避免直接写 `<` 导致 GitHub 页面从此处截断公式。大于号可使用 `\gt` 保持写法一致。
- **避免不兼容宏**：不要使用已发现 GitHub 渲染不支持的 `\phantom`；如需对齐，优先简化表达式或拆成短公式。
- **移动端排版**：避免将完整量词、等价关系与不等式放在一条过长的公式中；优先用正文说明量词，再使用多个独立的短 `math` 公式。`aligned` 并非一律不支持，但嵌套、换行或宏兼容性更易出问题，使用前需在 GitHub 实际页面验证。

例如严格小于号应写为：

~~~markdown
```math
0\le f(n)\lt c g(n)
```
~~~
- 公式内尽量避免中文；中文解释放在公式外。
- 普通程序表达式（如 `nums1[i-1]`）使用行内代码标记，数学推导才使用数学公式。
- 尽量避免在同一行混用复杂的 Markdown 强调语法和多个数学定界符。

## 2. 示意图

- 算法划分、搜索边界等图形应提供真实图片文件，不以纯文本代码块冒充图片。
- 优先使用 SVG：矢量清晰，适合 GitHub 手机端阅读。
- 图片统一存放在 `images/<题目目录>/` 下，Markdown 使用相对路径：

~~~markdown
![两个有序数组的正确划分](images/leetcode-4/partition.svg)
~~~

- 图片应包含必要的标签、图例和替代文本，并确保手机端可读。

## 3. 发布前检查

1. 检查所有行内公式是否采用 `$\x60...\x60$`。
2. 检查独立公式是否采用 `math` 围栏代码块。
3. 检查上标、下标的花括号与公式命令；严格小于号使用 `\lt`，避免不兼容的 `\phantom`。
4. 检查 SVG 文件已提交且相对路径正确。
5. 在 GitHub 的实际 Markdown 页面（尤其手机端）检查公式有无**截断、横向溢出或不支持的宏**，以及图片是否正确显示。
